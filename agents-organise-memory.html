Can LLM agents organize their own memory?

A new paper lets an AI agent keep its memories as ordinary notes it writes and rearranges itself, each one tied back to the original conversation, and it scored highest on all three memory tests it faced.

An explainer of Fu, Qi and colleagues, City University of Hong Kong and Tencent, November 2026

A chatbot doesn’t learn from talking to you. Its knowledge is frozen when training ends, so anything it should remember from last week has to be written down somewhere outside it, like a notebook it can reread. Most memory systems decide in advance what that notebook looks like: fixed fields, fixed rules for filing. This paper asks a simpler question. What if the agent just kept ordinary notes, and decided for itself how to arrange them?

The dilemma every memory faces

Imagine helping a friend plan a team offsite over months of chats. If you keep the full transcript, nothing is lost, but finding the one line about the venue means rereading everything. If you keep tidy summaries, the venue is easy to find, but the detail that it was moved, and when, may have been smoothed away.

The method in this paper, called SoMem (self-organized memory), refuses to choose. It keeps both, and ties them together.

Three layers, one notebook

Source is the archive. Every message is stored exactly as it was said, and nothing is allowed to edit it.

Topic is a set of plain Markdown documents the agent writes itself. It picks the subjects and the headings, and decides when a topic should be split in two, merged with another, or rewritten because something changed.

Core is one short, size-capped note for things that should always be in mind: standing preferences, rules, frequently needed background. It’s placed at the start of every question, a bit like a system prompt.

Anatomy of one memory

The unit of memory is a paragraph. Each paragraph carries four things, which the paper writes compactly as

u = ( b, c, E, L )

Dates keep the precision of the original. If a message only said “in March”, the memory says March, not March 1.

A referee for every edit

Letting a language model freely rewrite its own memory is risky. It might drop a citation, or point a link at a paragraph that no longer exists. So the agent never edits memory directly. It proposes an edit, and plain code checks it first.

The split is deliberate. The model handles meaning, which it’s good at, and code handles bookkeeping, which it’s reliable at. One honest caveat: the checks guarantee the structure is sound, not that the content is true. A wrong summary with valid citations still gets through.

Three more views, for free

Some questions are about a topic. Others are about what connects to what, what happened when, or what came up lately. Rather than asking the agent to maintain four separate structures and keep them in sync, the runtime derives three extra views from the topic notes, automatically, after every accepted edit.

Same ten memories, four arrangements. Because the views are rebuilt from the notes rather than written separately, they can’t drift out of date.

Answering a question

At question time the agent isn’t handed a fixed bundle of retrieved snippets. It gets a few read-only tools (search, list files, read a file) and decides what to look at next based on what it just read.

The agent can take up to 20 rounds of this on one benchmark and 50 on the others. Being able to go back to the original message turns out to be the most important part of the whole design, as the next sections show.

How well does it work?

The authors tested on three long-term memory benchmarks, against six other memory systems and against simply pasting the whole history into the prompt (“Full Context”). Every method used the same model, GPT-6 Luna, both to build its memory and to answer.

The margins are modest, two to three points, but consistent. SoMem came first on all three benchmarks, and on all three it also beat handing the model the complete history.

What actually matters?

To find out which parts earn their keep, the authors froze one finished memory and switched pieces off at question time, one at a time, on all 1,540 LoCoMo questions.

Two parts clearly matter. Taking away the original messages costs almost 9 points; taking away the topic notes costs about 3. The organized notes help, but they complement the originals rather than replace them. The other pieces mostly shift which kinds of question go right. Removing the timeline or the graph, for example, costs a little on questions about time. Core changes nothing here, which is expected: this benchmark doesn’t test standing preferences, and that’s what Core is for.

One model writes, another reads

Because the memory is just Markdown files, any model can read what another model wrote. The authors had three models each build a memory, then had four models answer questions from each one.

Every pairing lands between 90 and 93.3 percent, so the notebook travels well. Readers also bring their own strengths to the same memory: DeepSeek V4 Flash beat GPT-5.6 Luna and Gemini 3 Flash on multi-step questions every time, while Qwen 3.8 Flash was consistently best on open-ended ones.

Thinking harder, sometimes reading less

Modern models can be asked to reason more before answering. Since SoMem lets the reader keep searching, extra reasoning has somewhere to go. Here is what happened on BEAM-100K as each model’s effort setting was turned up.

More effort mostly meant better answers. One surprise: when GPT-6 Luna went from high to extra-high effort, its score rose and its token use fell, because sharper searches meant fewer repeated lookups. The gains do level off. On the shorter LoCoMo histories, some models plateaued or slipped at the top setting.

The bill

Organizing memory with a capable model isn’t cheap. Here is the total cost of running the full LoCoMo benchmark with GPT-6 Luna, building memory and answering all 1,540 questions.

About half of SoMem’s cost is a one-time build ($118.85). After that, each question costs about 7 cents. Most of the spend is input text that gets reread, and two-thirds of it was already cached; with cached text billed at a tenth of the normal price, the total falls to $96.33. That is still many times more than the lightweight systems, in exchange for roughly 9 to 29 points of accuracy.

What the paper doesn’t show

The tests are all question answering over past conversations; they don’t cover long-running personalization or actually carrying out tasks. Answers were graded by another language model (GPT-4o-mini) with no human spot checks. The component tests were single runs on a frozen memory, so they show what each part does at question time, not how memory would have been built without it. And as noted, the referee checks structure, not truth. Catching an agent’s own mistakes as its memory grows remains an open problem.

So, can agents organize their own memory?

Here the answer is a qualified yes. Give a model plain documents and the freedom to arrange them, pair it with simple code that keeps the bookkeeping honest, and never throw the originals away. That last part matters most.
